# Ten Rush — 출시 준비 체크리스트

> Dice Battle 출시 때 쓴 체크리스트를 Ten Rush 기준으로 다시 정리한 것.
> 완료된 항목은 ✅, 아직 안 한 건 ☐로 표시. **최종 판단(언제 스토어에 올릴지,
> 어떤 항목을 스킵할지)은 항상 개발자 본인 몫** — 이 문서는 빠뜨리기 쉬운
> 걸 미리 보여주는 용도.

---

## 1. 빌드/코드 준비

- ✅ 패키지명 확정: `com.onepixel.tenrush`
- ✅ companyName/productName: `OnePixel` / `Ten Rush`
- ✅ 화면비 9:16 고정 + 레터박스 (기기별 화면비 대응)
- ☐ **앱 아이콘** — 아직 기본 유니티 아이콘. Play 등록 전 필수(512×512 고해상도 + 적응형 아이콘)
- ☐ **버전 번호/버전 코드** — `Player Settings → Version`, `Android → Bundle Version Code`.
  최초 출시는 보통 `1.0.0` / 코드 `1`
- ☐ **최소/타겟 SDK 버전 확인** — Google Play는 매년 최소 targetSdkVersion 요건을
  올린다. [Play 콘솔 요건](https://developer.android.com/google/play/requirements/target-sdk)에서
  현재 연도 기준 최소치 확인 후 Player Settings에 반영
- ☐ **릴리즈 키스토어 생성 및 안전 보관** — `.gitignore`에 이미
  `*.keystore`/`*.jks` 제외돼 있음(절대 커밋 금지). 분실하면 앱을 영원히
  업데이트할 수 없으니 별도 백업(비밀번호 관리자 등) 필수
- ☐ **Android App Bundle(.aab)로 빌드** (.apk 아님 — Play는 AAB 필수)
- ☐ 실기기(에뮬레이터 아닌 실제 안드로이드 기기)에서 최종 플레이 테스트
  - 다양한 화면비(18:9, 20:9, 태블릿 등)에서 레터박스 확인
  - 광고(리워드 +15초, 전면) 실제 노출 흐름 확인
  - 뒤로가기 버튼 동작 확인(종료 확인창/타이틀 복귀 확인창)

## 2. 개인정보처리방침 / 데이터 안전

- ✅ `docs/privacy-policy.html` 작성 완료(한국어+영어)
- ☐ **GitHub Pages 공개 확인** — 저장소는 이미 Public + Pages `/docs` 활성화됨.
  커밋·푸시 후 실제로 `https://puddingnote.github.io/TenRush/privacy-policy.html`
  접속되는지 확인
- ☐ **Play Console "데이터 안전(Data Safety)" 양식 작성** — 아래 내용과
  반드시 일치해야 함(방침 문서를 쓰면서 동시에 이 양식도 같이 채울 것):
  - 광고 ID 수집: **있음**
  - 기기/기타 ID 수집: **있음**(AdMob)
  - 사용자 데이터 서버 전송: **없음**(자체 서버 없음)
  - 데이터 판매: **없음**
- ☐ 개인정보처리방침 URL을 Play Console 앱 콘텐츠 설정에 등록

## 3. 광고/정책

- ✅ AdMob 연동 완료(실제 App ID/유닛 ID 적용됨)
- ☐ **Play 콘솔 "앱 콘텐츠 → 광고: 있음" 신고**
- ☐ **아동 대상 카테고리로 설정하지 않기** — 설정 순간 광고 정책이 훨씬
  엄격해짐(재사용 가이드 5장). 캐주얼 게임이지만 실제 타겟이 전연령/성인
  일반이면 아동 카테고리 피할 것
- ☐ **콘텐츠 등급 설문** 작성(Play 콘솔에서 진행, IARC 기준)
- ☐ **UMP(EU 동의 배너)** — 유럽 배포를 포함할지 결정 필요. 포함한다면 출시
  전에 반드시 붙여야 함(`docs/Monetization.md` "미룬 것" 참고). 배포 국가를
  한국/특정 국가로 제한하면 당장은 생략 가능
- ☐ Android 13+ `AD_ID` 권한 자동 추가 확인(보통 AdMob SDK가 자동 처리 —
  빌드 후 Manifest 확인 권장)

## 4. (미구현, 권장) 강제 업데이트 시스템

Dice Battle에서 쓴 원격 JSON 기반 강제 업데이트(`version.json` + fail-open
설계, 재사용 시스템 모음 1장)가 **Ten Rush에는 아직 없음**. 필수는 아니지만,
출시 후 치명적 버그가 발견됐을 때 구버전 사용자를 강제로 막을 방법이
없다는 뜻이라 강력히 권장됨. 출시 전에 붙일지, 1차 출시 이후에 붙일지는
판단 필요 — 나중에 붙이기로 하면 그 시점에 별도 논의.

## 5. IAP

- ✅ **하지 않기로 확정** — 광고 수익만으로 감(`docs/Monetization.md` 참고).
  이 섹션은 나중에 IAP를 하기로 마음이 바뀌지 않는 한 할 일 없음

## 6. Play Console 등록 정보

- ☐ 앱 제목, 짧은 설명, 긴 설명 작성
- ☐ 스크린샷(휴대전화 최소 2장, 권장 4~8장) — 9:16 화면 그대로 캡처하면 됨
- ☐ 앱 아이콘(512×512), 그래픽 이미지(1024×500)
- ☐ 배포 국가 선택
- ☐ 가격: 무료
- ☐ **내부 테스트 트랙으로 먼저 배포 권장** — 실기기 여러 대에서 광고/과금
  흐름 확인 후 프로덕션 승격

## 7. 출시 순서 (틀리면 위험한 부분)

강제 업데이트 시스템을 나중에 붙이게 되면, 그때는 아래 순서를 반드시 지킬 것
(재사용 시스템 모음 1장):
```
1. 새 버전 빌드 → 스토어 업로드
2. 스토어에서 "배포 완료" 상태 확인          ← 반드시 여기까지 기다린다
3. version.json 의 minVersion 을 올린다
4. 푸시
```
지금 당장은 강제 업데이트 시스템이 없으므로 해당 없음 — 붙이는 시점에 다시
참고.
