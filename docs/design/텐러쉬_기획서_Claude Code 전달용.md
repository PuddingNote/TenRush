# 텐러쉬 (Ten Rush) — 게임 기획서 (Claude Code 전달용)

> 프로토타입 테스트를 거쳐 확정된 버전. 그리드 배열 연산만으로 동작하며, 물리/중력 시뮬레이션이 전혀 없는 것이 이 게임의 가장 큰 장점.

---

## 1. 한 줄 컨셉

**"더해서 10, 그거면 끝."**
6×7 그리드에서 아무 타일 두 개나 짚어서 합이 10이 되면 제거되는 초단순 매치 퍼즐. 기존 "Number Match" 계열 경쟁작들이 전부 "시간 제한 없는 힐링" 포지션인 것과 달리, 텐러쉬는 **타이머+콤보가 있는 빠른 아케이드** 포지션으로 차별화.

---

## 2. 코어 조작

- 그리드 안 숫자 타일을 탭 → 선택(하이라이트)
- 다른 타일을 탭했을 때 두 값의 합이 **10**이면 즉시 제거
- 합이 10이 아니면 살짝 흔들리는 피드백 후 선택 해제, 방금 탭한 타일이 새 선택으로 이어짐 (재탭 없이 바로 다음 시도 가능)
- 인접 여부는 상관없음 — 그리드 어디에 있든 두 개만 고르면 됨

**왜 설명이 필요 없나**: "더해서 10"은 숫자를 아는 사람이면 나라/언어 상관없이 즉시 이해하는 규칙. 튜토리얼 텍스트 자체가 불필요함.

---

## 3. 확정된 핵심 로직: 제자리 리필

- 초기 설계는 "타일 제거 → 위 타일이 중력처럼 아래로 당겨짐 → 빈 자리는 맨 위에서 새로 채움" 이었음
- 프로토타입 테스트 결과, **그 자리에서 바로 새 숫자로 교체**하는 방식이 더 낫다고 판단 → 최종 반영
- 구현 관점 이점: 컬럼 재배치 로직이 통째로 사라지고 인덱스 두 개 값만 바꾸면 끝
- 플레이 관점 이점: 매치할 때마다 그리드 전체가 흔들리지 않아서 다음 짝을 스캔하는 흐름이 끊기지 않음
- 막힘 방지: 매치 후 그리드에 합 10 페어가 하나도 없으면 전체 리셔플

---

## 4. 진행 & 긴장감 구조

| 요소 | 내용 |
|---|---|
| 라운드 타이머 | 60초 카운트다운, 상단 바가 시간에 비례해 줄어듦, 10초 이하부터 경고색 |
| 콤보 | 1.5초 안에 연속 매치 시 콤보 배율 상승, 매치당 기본 10점 + (콤보-1)×5점 |
| 종료 조건 | 시간 종료 시 최종 점수 표시 후 즉시 재시작 가능 |

---

## 5. 왜 설명 없이도 재밌는가

- 규칙 이해: 즉시 (숫자 더하기)
- 실패해도 손해 없음: 오답 타일이 사라지지 않고 그대로 남아있어서 부담 없이 계속 시도 가능
- 성공 피드백: 타일이 사라지고 그 자리에 새 숫자가 바로 나타나 "다음 기회"가 즉시 주어짐 → 멈춤 없는 몰입

---

## 6. 아트 파이프라인

- 타일: 숫자 1~9, HSL 값으로 색상 자동 생성 (색상 에셋 제작 불필요, 코드로 전부 처리) — 정확한 공식은 12장 참고
- 필요한 실제 아트 리소스: 배경, HUD 아이콘 몇 개 정도가 전부
- 컬러 반응 요소(콤보 시 색 강조, 선택 시 글로우)는 셰이더 없이 CSS/Unity UI 애니메이션 수준으로 충분히 구현 가능
- **미결정 사항**: 숫자-색 고정 배정 방식을 "합 10 짝끼리 연관된 색(보색 등)으로 묶을지" 아직 결론 안 남 — MVP에서는 일단 무지개 순서(1~9)로 가고, 이후 반응 보고 조정 권장

---

## 7. 수익화 설계 — AdMob 기준 구체화

Google AdMob만 다뤄보셨다고 하셨으니, 실제로 어떤 광고 포맷을 어디에 붙일지와 필요한 SDK까지 정리했어요.

| 유형 | AdMob 포맷 | 삽입 지점 | 비고 |
|---|---|---|---|
| 시간 연장 | **리워드 전면(Rewarded Interstitial)** 또는 리워드 | 타임업 직후, "+15초" 버튼 | 시청 완료해야만 보상 지급되는 리워드 계열 사용 |
| 셔플권 | **리워드(Rewarded)** | 게임 중 "막혔다" 느낄 때 누르는 버튼 | 위와 동일한 리워드 광고 유닛 재사용 가능 |
| 게임오버 화면 | **전면(Interstitial)** — 선택 사항 | 게임오버 3~4회당 1번 정도로 빈도 제한 | 매판마다 띄우면 세션이 짧은 게임 특성상 이탈률이 크게 오를 수 있어서 빈도 제한 필수 |
| 배너 | 사용 비권장 | — | 6×7 그리드 + 타이머 UI가 이미 화면을 꽉 채워서, 배너를 넣으면 그리드가 눌리거나 오탭 유발 가능성 큼 |

**Unity 구현 시 필요한 것**:
- **Google Mobile Ads Unity 플러그인** (AdMob 공식 SDK) 설치
- **UMP(User Messaging Platform) 동의 플로우**: EU/영국 등 지역에서는 개인 맞춤 광고 표시 전에 동의 UI를 먼저 띄워야 함 (GDPR 대응, AdMob 플러그인에 포함되어 있음)
- 개발 중에는 **테스트 광고 유닛 ID**로 작업하고, 스토어 출시 직전에 실제 광고 유닛 ID로 교체 — 테스트 중 실제 ID로 광고를 반복 클릭하면 계정 정지 위험이 있으니 주의
- 리워드 광고는 "로드 완료 후 노출"이 기본이라, 버튼을 누른 시점에 광고가 아직 로드 안 됐을 경우의 처리(로딩 스피너 또는 버튼 비활성화)를 미리 만들어두는 게 좋음

**IAP는 AdMob과 별개**: 노애드/테마팩 구매는 Google Play 자체가 아니라 **Unity IAP 패키지**(스토어 내 인앱결제 연동)를 따로 붙여야 함 — AdMob SDK로는 처리 안 됨.

## 8. 기술 스택 (Unity 이식 기준)

- 2D UI Grid (UGUI GridLayoutGroup 또는 단순 좌표 배치)
- 로직: `int[,] grid` 2차원 배열 + 인덱스 값 교체만으로 전체 게임 로직 완성
- 애니메이션: DOTween으로 제거 시 스케일 축소, 새 타일 등장 시 페이드인 — Rigidbody/Physics2D **완전 불필요**
- 오디오: 매치 성공 사운드 + 콤보 단계별 피치업 정도로 충분한 손맛 확보 가능
- 광고/IAP: Google Mobile Ads Unity 플러그인 + Unity IAP

## 10. 화면 흐름 (MVP 기준)

"설명 없이 바로 이해" 원칙에 맞춰 타이틀 화면 없이 **바로 플레이 진입**을 기본으로 제안:

```
앱 실행 → 플레이 화면 (그리드 + HUD 즉시 표시, 타이머 시작)
        → (시간 종료) → 게임오버 오버레이 (점수 + 다시하기 버튼)
        → 다시하기 탭 → 플레이 화면 재시작
```

## 11. 구현 상수 정리 (Claude Code 참고용)

프로토타입에서 이미 튜닝을 마친 값들. 최초 구현 시 이 값 그대로 사용 권장, 이후 밸런싱 단계에서 조정.

| 상수 | 값 |
|---|---|
| GRID_ROWS | 7 |
| GRID_COLS | 6 |
| 타일 숫자 범위 | 1~9 (균등 랜덤) |
| 타일 색상 | `hue = (숫자값-1) * 40`, `HSL(hue, 70%, 60%)` |
| ROUND_TIME | 60초 |
| 타이머 경고 임계값 | 10초 이하부터 경고색 |
| COMBO_WINDOW | 1500ms (1.5초 안에 연속 매치 시 콤보 유지) |
| 기본 획득 점수 | 매치당 10점 |
| 콤보 추가 점수 | (콤보 단계-1) × 5점 |
| 막힘 방지 | 매치 후 그리드 전체에 합 10 페어가 없으면 전체 리셔플 |

## 12. 레퍼런스 로직 (검증된 프로토타입 — 그대로 포팅 권장)

아래는 실제로 플레이 테스트를 마친 핵심 로직(JS)입니다. Unity/C#으로 옮길 때 이 흐름을 그대로 따라가면 프로토타입과 동일한 느낌을 보장할 수 있습니다.

```javascript
// 두 타일 선택 → 합 10 체크 → 매치 성공 시 처리
function onCellClick(r, c){
  if(gameOver || locked) return;

  if(selected && selected.row===r && selected.col===c){
    clearSelection();
    return;
  }
  if(!selected){
    setSelected(r, c);
    return;
  }
  const sum = grid[selected.row][selected.col] + grid[r][c];
  if(sum === 10){
    doMatch(selected, {row:r, col:c});
  } else {
    flashMismatch(selected, {row:r, col:c});
    clearSelection();
    setSelected(r, c); // 오답 타일이 바로 다음 선택으로 이어짐
  }
}

// 매치 성공 처리: 콤보 계산 → 제자리 리필 → 막힘 방지 체크
function doMatch(a, b){
  locked = true;

  const now = performance.now();
  comboCount = (lastMatchAt && now - lastMatchAt < 1500) ? comboCount + 1 : 1;
  lastMatchAt = now;
  const gained = 10 + (comboCount - 1) * 5;
  score += gained;

  // 애니메이션 딜레이 후 실제 그리드 갱신 (여기선 180ms)
  setTimeout(() => {
    grid[a.row][a.col] = rand19();
    grid[b.row][b.col] = rand19();

    if(!hasValidPair(grid)){
      grid = randomGrid();
      ensurePlayable();
    }
    renderAll();
    locked = false;
  }, 180);
}

// 막힘 방지: 그리드 전체에서 합 10 페어가 하나라도 있는지 확인
function hasValidPair(g){
  const flat = g.flat();
  for(let i=0;i<flat.length;i++){
    for(let j=i+1;j<flat.length;j++){
      if(flat[i] + flat[j] === 10) return true;
    }
  }
  return false;
}

function rand19(){ return 1 + Math.floor(Math.random()*9); }
```

**타이머 로직**: 1초마다 `timeLeft--`, 0 이하가 되면 게임오버 오버레이 표시. 타임바 너비는 `timeLeft / ROUND_TIME * 100%`로 갱신.
